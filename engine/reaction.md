# 反応の機構 — 態度・噂・成否・新設定を表と出目で決める

## 解く問題

TURNLOG で「記録」は機械化したが、「決定」は GM の裁量に残っていた。
NPC がどれだけ気を悪くするか、目撃が噂になるか、行動が成功するかを GM が
その場の判断で決めると、同じ行為への反応が手ごとにぶれ、後で食い違う。
GM が本文で口にした新しい設定（「四十年ぶりでございます」）も、どこにも書き戻されず、
既存の設定（「三十年仕えた」）と矛盾したまま残る。

対策は機構に埋める。**裁量は「player の行動を閉じた語彙で分類する」一点に絞り、
その先は表と出目で決める。** 分類と出目は本文より先にログに残し、ゲートで検算する。

### 処理の順番（毎手・固定）

```
1. 抽選     tools/draw.py（→ event_draw.md）
2. 分類     行動を行為タグと難易度に分類し、TURNLOG の「行為」「判定」に書く
3. 判定     難易度が自動でなければ roll.py check
4. 態度     行為の対象・その場の名前付き NPC ごとに roll.py regard
5. 噂       目撃があり行為タグが中立でなければ、噂を 1 件作る
6. 台帳     state.yaml を出目どおりに更新
7. 本文     更新後の state に基づいて書く。新しい設定を口にしたら同じ手で書き戻す（§4）
8. 記録     TURNLOG にエントリを追記
```

時刻が一区切り進んだら `roll.py spread`、NPC と（その日）初めて顔を合わせたら `roll.py meet <npc>`。

## 1. 行為タグと NPC の態度

### 1.1 NPC が持つもの（state.yaml の npcs）

```yaml
- { id: berta, regard: 0, cares: [金, 敬意], area: haselt, spot: 南門前, alive: true }
```

- `regard`（好感）: −3〜+3 の整数。初期値はその NPC を登場させたときに決め、以後は出目でしか動かない。
- `cares`（気にかけること）: 下の 8 語から 1〜3 個。登場時に決め、以後変えない。
  **金・敬意・体面・秩序・安全・家族・信仰・自由**
- `area`（町・村などの単位）と `spot`（その中の場所）: 噂の届く範囲の判定に使う。

### 1.2 行為タグ（閉じた語彙）

player の行動を、影響を受ける NPC ごとに次のどれか 1 つに分類する。

| タグ | 触れる cares（+ は好感↑、− は好感↓） |
|------|------|
| 助ける | 安全+ 家族+ |
| 与える | 金+ |
| 果たす（約束・義務・支払いを） | 秩序+ 敬意+ |
| 敬う | 敬意+ 体面+ |
| 寄進する | 信仰+ |
| 中立 | — |
| 無視する | 敬意− |
| 茶化す | 敬意− 体面− |
| 侮る ※ | 敬意− 体面− |
| 破る（約束・義務を） | 秩序− 敬意− |
| 欺く（露見したとき） | 敬意− 秩序− |
| 奪う | 金− 秩序− |
| 脅す | 安全− 自由− |
| 害する ※ | 安全− 家族− |

※ は強い行為。触れた cares 1 つにつき ±2。

### 1.3 計算（roll.py regard）

1. 基本値 = その NPC の cares のうちタグが触れるものの合計（±1、強い行為は ±2）。±2 で頭打ち。
2. d6 で強さ: **1 = 受け流す（0）／2〜5 = 基本値／6 = 倍**（±3 で頭打ち）。
3. 行為の対象でなく、その場で見ていた名前付き NPC は `--bystander`：結果を ±1 に丸める。
4. 新しい regard = 旧 regard + 結果（−3〜+3 に収める）。

基本値が 0（cares に触れない）なら出目は振らず、変化なしと記録する。

### 1.4 好感の帯（NPC の振る舞いを縛る）

| regard | 帯 | 振る舞い |
|--------|----|----------|
| −3 | 敵対 | 積極的に妨害する |
| −2 | 不信 | 頼みを断る。知っていることを話さない |
| −1 | 冷淡 | 義務の範囲だけ応じる |
| 0 | 中立 | 聞かれたことに通り一遍に答える |
| +1 | 好意 | 聞かれれば知っていることを話す（REVEAL partial まで） |
| +2 | 信頼 | 自分から打ち明ける（REVEAL full まで） |
| +3 | 忠誠 | 危険を冒して力を貸す |

**NPC の発話をチャネルにした REVEAL は、この帯が上限になる。** 帯を超える開示は、
文書・観察・脅しの成功など、別のチャネルを要する。

## 2. 噂

### 2.1 発生（自動）

TURNLOG の「目撃」が「—」でなく、「行為」に中立以外のタグが 1 つでもあれば、**必ず**噂を 1 件作る。
噂にするかどうかは判断しない。

```yaml
rumors:
  - { id: rm_m3_dance, origin_move: 3, tag: 茶化す, about: "新しい領主が陳情の最中に踊った",
      area: haselt, spot: 南門前, witnesses: 3, reach: 0, distorted: false, frozen: false, heard_by: [] }
```

- `tag` は噂になる行為タグ（その手で最も重いもの）。`witnesses` は目撃者の人数（名前の無い者も数える）。
- 目撃した名前付き NPC は、発生時点で `heard_by` に入れる（態度はその場の roll.py regard で処理済み）。
- PC が口止めに成功したら `frozen: true`。以後広がらない。

### 2.2 伝播（roll.py spread）

時刻が一区切り（例: evening → night）進むたびに、凍結されておらず reach<3 の噂すべてに d6 を振る。

- **d6 + (目撃者 3 人以上なら 1) ≥ 4 で reach +1。**
- **素の d6 が 1 なら尾ひれ**：`distorted: true`、tag が一段重くなる
  （茶化す→侮る、無視する→侮る、侮る→脅す、脅す→害する、欺く→奪う）。
- reach: 0 = 目撃者だけ／1 = 同じ spot／2 = 同じ area／3 = 全域。

### 2.3 伝聞（roll.py meet）

PC が名前付き NPC と顔を合わせたら、その NPC に届いていて（reach と area/spot で判定）、まだ
`heard_by` に無い噂について、噂の tag で §1.3 を `--bystander` 扱いで計算する。
NPC を `heard_by` に加える。尾ひれのついた噂は、重くなった tag で効く。

## 3. 行動の成否（roll.py check）

失敗しうる行動は、次の 5 段の難易度に分類して d20 を振る。

| 難易度 | 目標値 | 目安 |
|--------|--------|------|
| 自動 | — | 誰にも妨げられず、失敗しても意味のない行動（歩く・見る・踊る・くすぐる） |
| 易 | 8 | 素人でもたいてい成功する（荷を担ぐ、顔見知りに頼みごと） |
| 並 | 12 | 心得があれば成功する（値切る、警戒している者から聞き出す） |
| 難 | 16 | 熟練者でも半々（見張りの目を盗む、敵意ある者を説き伏せる） |
| 至難 | 20 | 熟練者でもまれ（衛兵の槍を素手で奪う） |

- **d20 + 修正 ≥ 目標値で成功。** 素の 20 は常に成功、素の 1 は常に失敗。
- 修正: 説得・頼みごとなど相手のいる社会的行動では、相手の regard を足す。
- 失敗したら行動は果たされない。その結果どうなるかは、世界の状態（state・Canon）から導く。

## 4. 新設定の書き戻し

本文や NPC の台詞で、world/・facts/・state.yaml のどこにも無い世界の事柄を口にしたら
（過去・人間関係・数値・地名など）、**同じ手のうちに書き戻す。**

- 該当する world/*.md（真実の側）に追記する。既存の記述と食い違うときは、両立する形に
  調停して書き、調停したことも書く。両立できなければ、その台詞は NPC の誤解か嘘として
  facts/ に DISINFO で載せる。
- CHANGELOG に 1 行: `CANON+  move=<n>  file=<path>  : <追記した内容の要約>`
- TURNLOG の「新設定」に `<path>: <要約>` を書く（無ければ「—」）。

ゲートは「新設定」と CANON+ 行の対応と、file の実在を検査する。内容の意味的な食い違いは
機械では検出できないので、セーブ時の監査で CANON+ の一覧を world の記述と突き合わせる。

## 5. 記録の書式（CHANGELOG）

roll.py が書く:
```
ROLL  move=<n>  kind=regard  npc=<id>  tag=<tag>  hits=<cares>  d6=<r>  delta=<d>  before=<b>  after=<a>
ROLL  move=<n>  kind=hear    npc=<id>  rumor=<id>  tag=<tag>  hits=<cares>  d6=<r>  delta=<d>  before=<b>  after=<a>
ROLL  move=<n>  kind=check   band=<難易度>  dc=<n>  d20=<r>  mod=<m>  total=<t>  result=<success|fail>
ROLL  move=<n>  kind=spread  rumor=<id>  d6=<r>  bonus=<b>  reach=<x>→<y>  distorted=<bool>  tag=<tag>
```
GM が書く:
```
CANON+  move=<n>  file=<path>  : <要約>
```

## 6. ゲートの検査（TURNLOG.md があるとき）

| # | 検査 | FAIL 条件 |
|---|------|-----------|
| P | 新設定 | TURNLOG の「新設定」と CHANGELOG の CANON+ 行が手ごとに対応しない／file が無い |
| Q | 好感照合 | NPC の regard が、その NPC の最後の ROLL（regard/hear）の after と一致しない／範囲外 |
| R | 噂の発生 | 目撃があり中立以外の行為がある手に、origin_move がその手の噂が無い／噂の reach が最後の spread の結果と一致しない |
