# TRANSCRIPT 仕様 — 手番ごとの生ログ

## 解く問題

TURNLOG は要約であり、GM が書いた本文そのものではない。NPC の口調、
台詞の言い回し、描写の細部（「四十年ぶりでございます」のような一言）は
要約で落ちる。だが矛盾は、まさにその細部から生まれる。後から「誰が何と言ったか」を
原文で確かめられなければ、新設定の書き戻し漏れや言い回しの食い違いを追えない。

対策: **player の入力と GM の本文を、手ごとに原文のまま `TRANSCRIPT.md` に追記する。**
TURNLOG と同じ手番で対応づけ、要約から原文へ辿れるようにする。

---

## 1. 位置づけ

| | TRANSCRIPT.md | TURNLOG.md |
|---|---|---|
| 中身 | 入力と本文の原文 | 処理の要約（分類・出目・反応・目撃・新設定） |
| 用途 | 「実際に何と書いたか」の確認 | 検索・照合・ゲート検査 |
| 粒度 | 1手 | 1手（同じ move 番号） |

- 本文は player に見せたものなので、Canon は含まない（GM 契約第1条で本文に出ていないはず）。
- 正本ではない。状態は state.yaml と facts/ が正（第7条）。

## 2. 書式（append-only・原文のまま）

````
## move <n> | <clock>

### 入力
<player の入力を一字一句そのまま>

### 本文
<GM が送った本文を一字一句そのまま>
````

- 誤字も含めて手を入れない。書き直したくなったら、次の手の本文で直す。
- OOC の相談・セーブ・監査は手ではないので載せない（→ `event_draw.md` §1）。
- 本文に `## ` で始まる行を書かない（区切りと衝突する）。

## 3. 検索（Python 版）

```bash
python3 tools/turnlog.py <campaign> --npc oswald --raw   # TURNLOG で絞り、該当手の原文も表示
python3 tools/turnlog.py <campaign> --text 四十年 --raw  # 文字列は TURNLOG と TRANSCRIPT の両方を探す
```

## 4. ゲートの検査（TRANSCRIPT.md があるとき）

| # | 検査 | FAIL 条件 |
|---|------|-----------|
| S | 生ログ対応 | TRANSCRIPT の move が TURNLOG の move と一致しない（欠番・余分）／入力か本文の節が無い |

## 5. コード無し版

チャット欄そのものが生ログである。GM が本文を書き写し直すと、長さの割に改変の危険が
大きいので、**生ログはチャットの書き出し（共有リンク・コピー）を player が保管する**。
GM はセーブ時に TRANSCRIPT を出力しない。
