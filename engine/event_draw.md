# イベント抽選 — 一手目から展開を確率で駆動する

## 解く問題

一手目に事件を置くと、player は世界を見渡す前に反応を迫られ、選択肢が
GM の用意した一本に収束する。逆に事件を一切置かないと、LLM の GM は
「静的な情景 → どうしますか？」に流れ、世界が動かない。

対策は気分ではなく機構に埋める。**一手目を含む GM の各手で抽選し、
出目が事件の有無と規模を決める。** 一手目だけは大イベントを出さず、事件が出ても
見渡しの余白を残す（→ OPENING_PROTOCOL 条件4）。
GM が「そろそろ何か起こそう」と判断する経路を塞ぐ。

---

## 1. 手番の数え方

- **手 = GM の応答 1 回。** `state.yaml` の `meta.move` に現在の手番を持つ（点値）。
- 開幕前の `meta.move` は 0。抽選するたびに +1 する。
- **1手目（move=1）も抽選する。ただし大イベントは小イベントに格下げする。**
  事件が出ても、それは見回せる方向の一つとして場面の縁に置き、場面を占めさせない（→ OPENING_PROTOCOL 条件4）。
- GM は応答のたびに抽選する。OOC の相談・セーブ・監査は手に数えない。

## 2. 抽選表（既定）

各手で `d20 + meta.tension` を振る。

| 合計 | 結果 | tension |
|------|------|---------|
| 1–15 | 平穏（事件なし。player の行動の結果だけを書く） | +1 |
| 16–19 | **小イベント** | 0 に戻す |
| 20以上 | **大イベント** | 0 に戻す |

- `tension` は平穏が続くほど事件が起きやすくなる圧。上限は 5（それ以上は加算しない）。
  素の確率は 平穏75% / 小20% / 大5%。平穏が5手続くと 小45% / 大30%。
- **大イベントは出目20以上でも、直前の大イベントから 3 手以内なら小イベントに格下げ**する
  （大事件の連打を防ぐ）。
- 表の数値はキャンペーンごとに `state.yaml` の `meta.draw_table` で上書きしてよい。

## 3. 事件の中身

規模は抽選が決め、**中身は GM が `world/04_events.md` のプールから選ぶ**。

- **小イベント**: 局所的・日常的。時間的な圧は弱い。隠し事実への扉を開けてもよいが、
  急がせない（陳情・噂・来客・天候・小さな事故）。
- **大イベント**: 勢力の一手や、隠し事実に根ざした圧。player に 1 アクション以内の
  反応を迫ってよい。
- 選ぶ基準は「いまの場面と矛盾しない」「直前と同じ id を連続させない」。
  プールに合うものが無ければ、Canon と矛盾しない範囲で新規に足し、
  `04_events.md` と CHANGELOG の世界ギャップ欄に記録する。
- **事件は場面を奪わない。** player が会話や作業の途中なら、事件は場面の縁から
  届く（扉を叩く音、待たせている使者、遠くの鐘）。その手の本文のうちに必ず表出させる。
- **一度使った事件 id は `used: true` にする**（再発させたい定例行事などは `repeatable: true`）。

## 4. 乱数の出どころ（GM が出目を作らない）

LLM が自分で「振ったことにする」と、出目は物語の都合に寄る。だから出目は外から来る。

- **Python 版**: `python3 tools/draw.py <campaign>` が `secrets` で d20 を振り、
  tension を加えて結果を判定し、CHANGELOG に `DRAW` 行を追記する。GM はその結果に従う。
- **コード無し版**: player がセッション開始時に **乱数列**（d20 を 20 個ほど、
  ダイスアプリ等で）を渡す。GM は先頭から順に消費し、使った位置を `meta.rng_cursor` に持つ。
  使い切ったら OOC で次の列を求める（fail-closed。自分で作らない）。

## 5. 記録

抽選結果は本文に出さない（第4条・監査の隔離）。CHANGELOG の状態操作欄に：

```
DRAW   move=<n>  d20=<r>  tension=<t>  total=<r+t>  tier=<calm|small|major>  at=<clock>
EVENT  move=<n>  id=<event_id>  tier=<small|major>        # 事件が出たときだけ
```

DRAW 行は乱数の出どころ（draw.py または乱数列）が書き、EVENT 行は GM が書く。
出目を書く手と事件を選ぶ手を分けることで、「都合のいい出目」を後から作れなくする。

state.yaml の更新は `meta.move` と `meta.tension`（大イベント時は `meta.last_major_move`）（と使えば `meta.rng_cursor`）の上書き、
使った事件の `used: true` だけ。

## 6. 季節注入との関係

季節注入（→ `season_inject.md`）は**隠し事実を増やす**機構、イベント抽選は
**表出の頻度を決める**機構。前者が霧を作り、後者が霧に風を入れる。
大イベントは隠し事実のうち未開示のものを優先して扉にする。
