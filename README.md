# llm-trpg-engine — LLMをGMにして遊ぶ、開示駆動のTRPGエンジン

**世界の真実はGMだけが握っている。プレイヤーは尋問・文書・噂・観察を通じて、
それを少しずつ「開示」させていく。**

情報が既定でブラインドで、開示そのものが遊びのループになる。そんなTRPGを
チャットLLMに回させるためのエンジンです。

- **markdown と YAML だけで動く。** 起動プロンプトを貼れば、Gemini / ChatGPT / Claude のどれでも始まる。
- **キャラクター作成が無い。** PCは会話の中で自然に決まる。物語は、すでに動いているイベントの只中から始まる。
- **ゼロ状態で配布。** 世界設定もキャンペーンも入っていない。`world/` と `facts/` を埋めた瞬間から、あなたの世界が始まる。
- **長く遊んでも設定が崩れにくい。** 事実と数値を「指示」ではなく「機構」で守る（→ [アンチドリフト](#アンチドリフト--長いセッションを壊さない仕組み)）。

## どんなゲームか

### 情報は既定でブラインド

世界の真実（**Canon**）を知っているのはGMだけ。プレイヤーに届く情報は、必ず
NPCの発話・文書・観察可能な出来事といった**チャネル**を伴う。GMが地の文で
真相を語ることは禁じられている。

- ❌ 「水先案内人は実は敵の内通者だ」（地の文で漏れている）
- ✅ 捕虜が吐いた——「水先案内人？ ああ、あいつは"向こう側"の人間だよ」

開示にチャネルを必須にすることが、そのまま没入の担保になる。

### 開示は3つの動詞で進む

| 動詞 | 意味 |
|------|------|
| `REVEAL` | 真実の一部をプレイヤーに明かす。`hidden → partial → full` の一方向のみ。後退しない |
| `DISINFO` | NPCが意図的に嘘をつく。プレイヤーの認識を真実からずらす。誰の嘘かを必ず記録する |
| `CORRECT` | 嘘や誤解が解け、認識が真実に戻る |

ひとつの事実の一生は、たとえばこうなる。

```
DISINFO  pilot_loyalty  belief="水先案内人は中立の技術者"  source=二重間諜     at=autumn.d11
REVEAL   pilot_loyalty  partial  via=尋問(捕虜)                           at=autumn.d14
CORRECT  pilot_loyalty  via=証拠露見(積荷台帳)                            at=autumn.d16
REVEAL   pilot_loyalty  full     via=証拠露見(積荷台帳)                   at=autumn.d16
```

誰も知らない → 偽情報で誤認する → 尋問で断片が漏れる → 物証で嘘が割れる → 真相確定。
**この4行が、プレイヤーの知識のバージョン履歴であり、物語のプロットそのもの**になる。

### キャラ作成なし、一手目からイベントの只中

GMは「キャラクターを作ってください」と尋ねない。能力値も生い立ちも先に埋めさせず、
PCはプレイヤーが状況にどう反応するかを通じて立ち上がる。PCの台詞・内心・決定は
プレイヤーのもので、GMは書かない（player主権）。

最初のGM発話は、静的な情景描写ではなく、動いているイベントの只中から。
規模は小さく、含みは大きく。

> 夜明け前、城門の衛兵が叩き起こしに来る——使者が一人、門前で倒れた。
> 意識はない。手には封蝋の押された書状。宛名は"この地の主"とだけある。

「あなた」が何者かも、書状の中身も、まだ書かれていない。プレイヤーが動いて初めて、
PCと世界が同時に立ち上がる。→ [engine/OPENING_PROTOCOL.md](engine/OPENING_PROTOCOL.md)

### 毎季、新しい霧が湧く

既知が増えると残りのブラインドが痩せ、終盤で緊張が消える。これを防ぐため、
毎季、外部アクター（近隣領・商会・宮廷など）が新規の隠し事実を **0〜2件** 注入する。
0件を許すので、静かな季節が挟まり、霧の濃淡そのものがリズムになる。
→ [engine/season_inject.md](engine/season_inject.md)

### 相性のよい題材

統治・諜報・外交のように、情報の非対称そのものが物語を動かす題材。スパイ、二重間諜、
尋問といったフィクション上の手段が、そのままエンジンの開示機構になる。
エンジンに題材は焼き込まれていないので、世界は自由に差し替えられる。

## 遊んでみる

1. [START_HERE.md](START_HERE.md) の**起動プロンプト**をチャットに貼る。
2. 既存の世界（`world/*.md`・`facts/*.yaml`）を貼るか、**種**（premise・トーン・舞台の一言）だけ渡す。
   種なら、GMが一緒に世界を立ち上げる。
3. 遊ぶ。保存したくなったら「**セーブ**」と言う。GMが監査を実行して、スナップショットと進行メモ（JOURNAL）の追記分を出すので、
   それを保管し、次回の冒頭に貼る。続きから再開できる。

Pythonは要りません。

## 自分の世界を作る

```bash
# 空の雛形をコピーして始める
cp -r campaigns/_template campaigns/myworld
```

- `world/*.md` — 世界の人間可読ビュー（地理・人物・勢力・経済…）。GM専用の「真実の側」。
  まず 01〜03（地理・人物・勢力）を埋めて骨格を作る。
- `facts/*.yaml` — **伏せたい真実を1事実=1ファイルに切り出す。** 開示の単位。
- `state.yaml` — 所持金・在庫・位置・時刻などの数値の台帳。

事実は、真実・開示・認識の三つを1ファイルに持つ。

```yaml
id: example_harbor_pilot
subject: 水先案内人
canon: "水先案内人は敵対商会に雇われた内通者。港の防備情報を流している"

revealed:                      # プレイヤーに明かした分
  status: partial              # hidden → partial → full
  to_player: "水先案内人の素性には不審な点がある、との証言を得た"
  channel: "捕虜の尋問"
  at: sample.d14

belief:                        # プレイヤーが信じていること
  player_thinks: "水先案内人は中立の技術者で、敵とは無関係"
  diverges: true               # 真実とずれている
  cause: "disinfo(二重間諜, sample.d11)"   # ずれの理由（誰の嘘か）
```

## 構造 — エンジンとキャンペーンの分離

```
llm-trpg-engine/
├── START_HERE.md   ← コード不要の始め方（起動プロンプト）
├── VERSION / CHANGELOG.md ← エンジンのバージョンと変更履歴
├── engine/         ← 全キャンペーン共通の機構（題材に依存しない）
│   ├── OPENING_PROTOCOL.md ← 開始の仕方（セッションゼロ・一手目イベント）
│   ├── GM_CONTRACT.md      ← GMが従う契約
│   ├── operations.md       ← REVEAL / DISINFO / CORRECT
│   ├── season_inject.md    ← 季節注入
│   ├── journal.spec.md     ← 進行メモ（JOURNAL.md）の仕様
│   ├── AUDIT_PROTOCOL.md   ← コード無しの監査手順
│   └── ...                 ← スキーマ・台帳操作
├── tools/          ← Python版ゲート（任意・厳密）
└── campaigns/
    ├── _template/  ← 空のキャンペーン雛形。コピーして始める
    └── <yours>/    ← あなたの世界。world/ facts/ state.yaml saves/ CHANGELOG.md JOURNAL.md
```

**engine/ と tools/ は一切キャンペーンに依存しない。** 固有名詞も世界設定も入っていない。
世界は `campaigns/<name>/` に閉じる。エンジンを1つ育てれば、複数のキャンペーンで使い回せる。

### 6つの機構

| # | 機構 | 役割 | 担当 | 実体 |
|---|------|------|------|------|
| 1 | **fact schema** | 事実を最小単位にし、Canon / Reveal / Belief を1つの事実の属性として持つ | 両方 | `facts/*.yaml` |
| 2 | **開示操作** | 情報の表出を `REVEAL` / `DISINFO` / `CORRECT` という型付き動詞にする | ゲーム | `engine/operations.md` |
| 3 | **GM契約** | 「チャネルなき情報表出は禁止」「数値は台帳を唯一の正とする」を憲法として固定する | 両方 | `engine/GM_CONTRACT.md` |
| 4 | **季節注入** | 毎季 0〜2 件の新規ブラインドを外部アクターから注入し、終盤の平坦化を防ぐ | ゲーム | `engine/season_inject.md` |
| 5 | **state 台帳** | 所持金・在庫・HP・時刻・位置・進行を「唯一の正」で管理し、価格参照と残高導出を強制する | アンチドリフト | `state.yaml` / `engine/state.schema.md` / `engine/state_ops.md` |
| 6 | **export gate** | 保存前に三層の関係と物質台帳の整合を監査し、違反があれば停止する | アンチドリフト | `engine/AUDIT_PROTOCOL.md`（コード無し）/ `tools/export_gate.py`（厳密） |

## アンチドリフト — 長いセッションを壊さない仕組み

このエンジンのもうひとつのテーマ。LLM製の長期セッションが死ぬ最大の原因は、
世界状態の**サイレントな腐敗（ドリフト）**である。コンテキストが伸びるほど指示は薄まり、
GMは自分がついた設定を忘れ、事実を捏造し、開示済みの情報を取り消す。
大半のプレイヤーはNセッション後に破綻し、原因も分からないまま離れる。

立場はひとつ。

> **正しさを「指示」の中に置くのをやめ、「機構」の側に移す。**
> 手順は忘れられる。仕組みは忘れられない。

LLMを「整合性制約のないDB」とみなし、外側から制約を足す。腐敗は二軸で起きるので、
どちらも同じ思想で塞ぐ。

- **認識の軸**（誰が何を知っているか）— 三層開示と `facts/` で守る
- **物質の軸**（いくら・何個・どこ・いつ）— 物質台帳 `state.yaml` で守る。
  「行き1銅貨・帰り6銅貨」型の破綻は、こちらの欠落で起きる

### 三層エピステミクス

ブラインドを開示していく設計は、単体では自立しない。下に三層が要る。

| 層 | 誰のものか | 真か | 監査での意味 |
|----|-----------|------|-------------|
| **Canon** | GM / 世界 | 常に真 | これに反するGM発話 = ハルシネーション |
| **Revealed** | プレイヤーの知識 | Canonの部分集合（append-only） | 縮んだら = 開示の消失（事故） |
| **Belief** | プレイヤーの認識 | Canonと乖離しうる | 乖離に理由がなければ = 事故、あれば = 仕様 |

三層を分けないと、**霧（意図されたブラインド）と誤り（LLMの事故）と嘘（意図された偽情報）が
混ざり**、開示設計はハルシネーションを鎮めるどころか増幅する。三層を切って初めて、
ゲートが「これは仕様の嘘」と「これは事故」を分離できる。

### export gate — 保存前の番人

保存前に監査し、違反があれば停止する。ゲートを通さない保存はしない。
その規律を人間の意志ではなく仕組みに預ける。

| 対象 | チェック |
|------|---------|
| 開示（`facts/`） | A スキーマ / B ラチェット（後退していないか）/ C 乖離の正当性 / D チャネル整合 / E 消失検出 |
| 物質台帳（`state.yaml`） | F 残高導出 / G 非負 / H 在庫実在 / I `save_seq` 単調 / J 価格参照 / K id一意 |

### 2つの運用

| | コード無し版 | Python版 |
|---|---|---|
| 実行環境 | どのチャットLLMでも | ターミナル / Code Interpreter |
| 監査の担い手 | LLM＋人間の目視 | 決定的なスクリプト |
| 見落とし | 起こりうる（人間が最終番人） | 起きない（同入力→同判定） |

普段はコード無しで回し、節目でPython版に通して検算する併用が堅い。

```bash
# キャンペーンを作り、世界と事実を埋め、セッションを回したら……
python3 tools/export_gate.py myworld            # 監査して、合格ならsavesを更新
python3 tools/export_gate.py myworld --dry-run  # 監査のみ。書き込まない
```

合格すれば `campaigns/myworld/saves/` を更新し、そのキャンペーンの `CHANGELOG.md` に追記する。
違反があれば停止し、何が壊れているかを表示する。
（`campaigns/` に実キャンペーンが1つだけなら名前は省略可）

## 今後 — 破綻せず、長く遊べること

このエンジンが目指す方向はひとつ。**破綻しないで、長く遊べること。** 改良はすべてこの一点に向ける。

- **検査の拡充** — Python版ゲートが、まだ見ていないものがある。時刻（`meta.clock`）の巻き戻り、
  クエスト進行やNPC状態の後退（倒れたNPCが復活する、など）。
- **コード無し版の精度向上** — 監査をLLM自身が行うため、見落としが起こりうる。

## 必要環境

- LLM（GMを務めるモデル。契約と機構はモデル非依存だが、長コンテキストを保持できるモデルほど機構の恩恵が大きい）
- Python版ゲートを使う場合のみ: Python 3.9+ と PyYAML（`pip install pyyaml`）

## バージョン

[Semantic Versioning](https://semver.org/lang/ja/) に従う。現行バージョンは [VERSION](VERSION)、
変更履歴は [CHANGELOG.md](CHANGELOG.md)（エンジン本体のリリースノート。キャンペーンごとの `CHANGELOG.md` とは別）。
既存キャンペーンの `facts/` や `state.yaml` がそのままでは使えなくなる変更は MAJOR を上げ、移行手順を添える。
